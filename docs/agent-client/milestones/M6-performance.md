# M6 体积与性能优化

状态：待启动。前置：M3 至 M5 的首版能力稳定，基线与候选配置一致。对应目标：G02、G09、G10，并复验受影响的功能目标。执行角色：性能、构建、前端和运行时。

## 目标

证明独立 Agent 产品在约定能力下更小、更快，并给出可复现的收益。性能目标以 [GOALS.md](../GOALS.md) 为准，测量流程以 [VALIDATION.md](../VALIDATION.md) 为准，本阶段不另设更宽松标准。

## 优化顺序

先移除不必要的入口、资源和初始化，再减少重复状态、全量扫描和无效渲染；随后优化事件传输与内存释放。只有 profile 证明某个计算热点值得替换时，才提出 Rust 实现。全量后端重写不作为本里程碑的前提。

不得通过删除首版必选扩展、隐藏浏览器服务、延迟下载必需运行时或排除子进程来制造收益。采用 Monaco 或额外浏览器引擎时，分别列出启用前后的尺寸与资源成本。编译压缩、缓存和 GC 条件对基线与候选保持一致。

## 交付物

计划在 `evidence/M6/` 保存性能原始数据、尺寸明细、进程归属、启动时间线、热点分析、改动和对应收益。报告必须同时给出 C0 与 C1；如果某配置能力不同，用能力差异说明结果，而不是合并成一个宣传数字。

## 验收门禁

- [ ] P01 至 P06 按统一样本量执行，包含中位值、p95 和未筛选的原始样本。
- [ ] 安装占用、空闲资源、冷启动和基本交互达到 G09 预算，C0 与 C1 各自满足匹配配置要求。
- [ ] T11 证明产物无 Electron、通用工作台前端和未许可编辑器扩展，动态资源与 worker 不漏算。
- [ ] 20 次会话循环和 30 分钟任务后没有无限队列、持续资源增长或自有孤儿进程。
- [ ] 固定工具任务没有通过调度和跨语言转发引入超预算开销，流式事件完整。
- [ ] 每项优化均保留必要功能和权限语义，复验对应 T03 至 T10 的受影响场景。

## 失败处理

若目标未达，先定位资源消耗属于 WebView、Host、Copilot 运行时、兼容宿主还是浏览器服务。提交按成本排序的改进项，保留原始比较。确需更改目标或首版范围时记录对用户体验的影响和新验收路径；在变更确认前不将 M6 标为完成。

## 推进记录与下一步

当前尚无执行证据。首先在完整能力配置上采样，再选择优化，禁止仅凭静态代码量断言收益。通过后将构建、配置和预算冻结为 [M7](M7-macos-release.md) 的发布候选输入。
