## 发布行为

应用包含必要运行时，用户不需要安装 VS Code 或系统 Node。首次启动需要联网登录和使用模型的条件在界面中说明；运行时如果按需获取，应验证来源、版本和完整性，且其占用计入完整安装成本。

关闭窗口保持应用和任务运行。退出时存在活跃任务就显示等待或停止选项；取消退出继续原任务。正常退出关闭自有 Host、运行时与扩展服务，外部进程不被误杀。异常退出后的首次启动能诊断并恢复已持久化会话，不把未落盘事件恢复作为保证。

数据回退先检查兼容性；不支持的旧版本应明确阻止不安全打开并提供保留副本的恢复路径，不直接以旧格式覆盖新数据库。用户升级前后有可定位的数据副本和恢复说明。

## 上游维护合同

每个发布记录 VS Code 源码提交、AHP 客户端与协议、Node、Copilot SDK、Copilot 运行时、Tauri 和扩展版本。优先将改动限制在独立入口与边界适配，避免复制大块上游逻辑而失去来源。

上游更新分为协议、SDK 与运行时、基础组件和扩展四类，先验证版本组合再合入发布分支。不要自动同步最新主线。版本组合变化要复验受影响的功能和性能；未变输入可复用已有结果。

## 交付物

正式安装产物、校验值、版本与第三方依赖说明、诊断导出、安装更新和恢复说明、全目标验收索引。证据计划存入 `evidence/M7/`，签名凭据和账户令牌使用受保护的发布环境管理，不进入文档。

- [ ] 干净 Mac 完成安装、登录、项目选择、真实修改、命令执行和 Diff 审阅，满足 T01、T05、T12。
- [ ] 签名、公证与隔离属性下首次启动通过；所有随包可执行文件和原生依赖可加载。
- [ ] 更新成功、更新失败、取消更新和数据兼容回退通过 T13；错误版本不会破坏数据。
- [ ] 正常退出无自有孤儿进程，崩溃后恢复已持久化会话，诊断包不含秘密或私有内容。
- [ ] G01 至 G12 都有有效证据，M0 的首版必选扩展与富交互清单全部通过。
- [ ] 用户说明准确区分兼容范围、可选能力和后续能力，提供当前版本支持的格式和扩展版本。

## 风险与处理

发布账户或公证条件尚不具备时，先完成可重复构建、开发包和不受影响的验证，保持“开发预览”状态。原生依赖或运行时分发出现问题时修复构建与签名链，不通过要求用户安装 VS Code 来满足独立产品验收。
