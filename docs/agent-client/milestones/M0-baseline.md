# M0 能力边界与性能基线

状态：待启动。前置：当前仓库和一台可用于测试的 macOS arm64 机器。对应目标：G01 至 G12 的验证输入，重点为 G08、G09、G10。执行角色：架构、运行时和测试；具体负责人在启动时登记。

## 目标

把“去掉编辑器、保留 Agent”转换为逐项可验证的能力边界，建立同能力性能基线，并确认实际 Copilot 登录与运行条件。完成后应能说明每个重要依赖为何保留、每项能力在哪个里程碑交付，以及哪些未知会阻塞路线。

## 输入和检查入口

- 当前源码、根目录构建配置、`src/vs/sessions`、`src/vs/platform/agentHost` 和 `extensions/copilot`。
- [方案总结](../SOLUTION.md)、[目标矩阵](../GOALS.md)和[验证规范](../VALIDATION.md)。
- 真实 Copilot 测试账户；仅使用账户类型和授权方式记录测试条件，不保存凭据。

## 能力清单要求

每项记录能力名称、用户行为、来源、当前实现、编辑器依赖、期望形态、验收场景与优先级。浏览器、Canvas、诊断、未保存缓冲区、云会话、远程连接和自动化调度必须有独立记录，不能归入含糊的“Copilot 全功能”。

没有指定真实第三方扩展时，用受控 fixture 建立最低兼容合同，并保留真实候选补录项。fixture 通过只证明对应 API 可用，不能宣传所有 Marketplace 扩展兼容。后续加入首版必选扩展需同步回归和资源预算。

## 交付物

计划在 `evidence/M0/` 保存能力矩阵、依赖清单、扩展候选清单、基线报告和决策记录。基线报告包含原始样本、机器配置、逐进程归属、构建与运行时版本，不只记录截图和平均数。

## 验收门禁

- [ ] G01 至 G12 均能定位验证场景，首版必选能力没有未归属项。
- [ ] 所有发布依赖含 worker、动态资源和原生模块均有清单；未知依赖明确列为待验证项及责任角色。
- [ ] 扩展兼容样本覆盖文件或配置工具、MCP 提供、声明式 Agent 资源；混合扩展单列。
- [ ] B1 按有无兼容宿主建立匹配配置，性能步骤可由另一执行者复现。
- [ ] 实际登录、产品配置、运行时获取和版本协商风险已经记录，阻塞项有验证顺序。
- [ ] 首版富交互清单和性能目标已确认；任何调整保留原因、时间和旧值。

## 风险与处理

若当前版本无法构建，先记录准确失败位置并完成不受影响的静态清单；未得到运行基线前不宣称 M0 已验收。若真实账户暂不可用，可推进 mock fixture，但真实登录与任务验证仍是 M1、M2 的必需门禁。
