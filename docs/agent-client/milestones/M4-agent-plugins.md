# M4 Agent 原生插件与自定义能力

状态：待启动。前置：M3 核心流程通过；M2 后可以准备格式审计和 fixture。对应目标：G06、G07、G11。执行角色：Host 适配、前端和插件测试。

## 目标

保留不依赖传统编辑器的 Agent 自定义能力，使用户能发现、配置和使用 MCP、Skills、自定义 Agent、指令、Prompts、Hooks 及插件。先支持已有协议和运行时确实支持的格式，不建立一套与 Copilot 冲突的插件生命周期。

## 能力清单

| 类型 | 首版需要验证的行为 |
| --- | --- |
| MCP | 受控 stdio 与 HTTP 服务的配置、启动、认证或明确的认证限制、工具发现、调用、失败与停用 |
| Skills | 从支持的位置发现、查看来源、启用并在任务中实际加载 |
| 自定义 Agent | 发现、选择、使用其指令和工具配置；与模型选择分别管理 |
| Instructions 与 Prompts | 明确用户与项目作用域，任务中实际生效；支持的格式和优先级沿用运行时 |
| Hooks | 按 Copilot 已支持的格式执行、显示失败与退出结果；禁用后不再触发 |
| 复合插件 | 发现资源、显示实际内容、执行支持的安装与移除流程，并正确更新运行会话 |

## 状态与执行约束

Host 或运行时决定某资源是否已加载，客户端不通过改显示状态假装安装成功。运行时管理的安装必须使用其支持的计划和确认流程；过期计划重新获取，不能用手工写文件绕过安装语义。

用户、项目与插件资源的来源都需要保留，两个项目的自定义能力不会串用。禁用资源之后，按运行时支持的生效边界更新新任务或重载会话，界面显示真实的待生效状态。

MCP 服务失败不等于 Agent 任务成功；认证失败、配置损坏、进程退出和工具超时要分别显示。不得因插件无效而放宽工具审批或扩大文件访问权限。

可管理的自定义能力界面、格式兼容表、测试资源集合、插件生命周期报告和已知限制，证据计划存入 `evidence/M4/`。直接 Marketplace 浏览可后续扩展，已支持资源的发现与生命周期不能依赖 Marketplace 可达。

## 验收门禁

- [ ] T08 中各项支持格式均在任务中实际生效；发现列表不是唯一证据。
- [ ] stdio 与 HTTP MCP 至少各有一个受控样本，覆盖正常调用、认证或认证限制、失败与重启。
- [ ] 复合插件能显示来源和包含的资源；安装、启用、禁用、卸载后状态与实际执行一致。
- [ ] 项目与用户作用域明确，切换项目和账户不复用错误的授权或资源状态。
- [ ] 安装确认对应实际内容，过期或取消不会继续应用；T07 对插件工具的拒绝路径通过。
- [ ] 不支持的格式和能力明确报告，不通过空实现、忽略 Hook 或吞掉错误伪装兼容。

## 风险与处理

如果当前 SDK 不支持某项资源的完整安装管理，可先提供运行时支持的本地资源加载，并明确限制；M0 必选的生命周期仍需完成或作为阻塞登记。Hook 和自定义 Agent 的跨 provider 格式不在本阶段泛化，避免把 Copilot 行为误认为通用协议行为。
