# M1 独立 Agent Host

状态：进行中（2026-10-28 首个独立构建与 Linux 确定性版本已实现）。前置：M0 清单和验证环境。对应目标：G01、G04、G06、G10、G11。执行角色：Node 运行时、构建和测试。

## 目标

从现有仓库提取可以单独构建、启动和分发的 Agent Host。它应在没有 VS Code 和 Electron 的环境中，执行真实 Copilot 文件与命令任务，为 Tauri 提供明确的生命周期和协议接口。

## 实现边界

复用现有 `agentHostServerMain` 和服务构造，首版构建只启用 Copilot provider。保留必要的 base、platform 和无界面的文本或 Diff 算法；不删除其他 provider 的源码。避免复用原有开发启动脚本中自动编译整套桌面应用的步骤。

工程位置为 `packages/agent-host/`，构建和打包脚本单独列出源文件、资源、Node 版本和原生依赖。产品配置与用户数据目录独立，不能在开发机上可运行就假定发布环境可用。

## 启动合同

- 默认仅监听回环地址，使用系统分配的可用端口，启动后发布可机读 readiness；端口冲突和启动失败是可区分错误。
- 连接令牌使用进程内生成并经受保护的文件或管道传递，不作为进程参数输出。精确方式在本阶段通过既有接口验证后固定。
- 账户认证和连接认证分开处理；真实登录不读取或复制现有 VS Code 登录缓存。
- Host 和运行时自行执行工具权限与持久化。客户端只提供交互，不拥有绕过审批的执行通道。
- 正常退出先停止接收新请求，处理活跃任务与持久化，再关闭 worker 和自有子进程；异常退出可以诊断，不能承诺恢复未落盘的最后事件。

## 验收门禁

- [ ] 不运行 Electron 或 VS Code，Host 可以从全新解压目录启动并完成真实 Copilot 任务。
- [ ] 工具能读写至少两个测试文件、执行确定性检查并返回结果；无界面权限路径仍有效。
- [ ] 错误令牌不能执行操作，账户过期和服务不可达有明确错误；凭据不进入命令行、日志和诊断输出。
- [ ] worker、WASM 和原生模块实际可加载，使用普通 Node 的 ABI 验证，而非沿用 Electron 二进制。
- [ ] 不依赖根目录开发依赖或现有 VS Code 目录；发布必需组件均计入产物清单。
- [ ] 正常停止、运行时故障与 Host 故障场景可复现，已有会话数据可再次打开。

## 风险与处理

如果某个服务从 Electron 获取能力，先为该服务建立独立接口或 Node 实现，不把 Electron 引入 Host 分发包。若 Copilot 服务配置或登录成为阻塞，保持 mock 路径用于后续界面准备，但不将真实任务门禁改成 mock 通过。
