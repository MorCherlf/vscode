# M5 Agent 工具扩展与富交互兼容

状态：待启动。前置：M3 与 M4 通过，M0 必选扩展和富交互清单已固定。对应目标：G06、G08、G10、G11。执行角色：扩展运行时、前端、浏览器适配和测试。

## 目标

去掉编辑器扩展的分发和激活，同时让适用的 Agent 工具扩展运行。对普通 VS Code 工具扩展使用精简 Node 扩展宿主，对浏览器与 Canvas 等富交互使用独立适配。兼容以固定版本和真实场景为单位，不承诺任意 VSIX。

## 三条工作线

| 工作线 | 推进方法 | 交付物 |
| --- | --- | --- |
| 工具扩展 | 以 Agent 贡献点筛选，再审计依赖和实际 API；按需启动兼容宿主 | 兼容清单、API 支持表和工具桥接 |
| 混合扩展 | 将工具逻辑与语言服务、编辑器、调试和工作台视图拆分；可转为 MCP 的给出迁移成本 | 每个必选扩展的兼容或迁移结果 |
| 浏览器与 Canvas | 把 Electron 专用视图与执行抽离；浏览器使用独立受控服务，Canvas 按已支持协议构造受限视图 | 首版必选富交互可用，其他能力准确显示状态 |

## API 与宿主边界

优先调查的 API 包括工具注册与调用、MCP 定义、资源贡献、配置、文件系统、项目目录、命令、日志和 SecretStorage；最终支持表由真实样本决定，不为未使用 API 提前重建整套 VS Code。

调用活动代码编辑器、调试器或自定义工作台视图的扩展，不自动判为兼容。缺失 API 应产生可定位错误，不能返回空对象让扩展继续运行。纯声明式 Agent 资源尽量直接提取，避免为读取静态文件启动 Node 扩展宿主。

工具来源与调用方保持对应，结果经过同一 Agent 工具路径返回；不能在注册时授予全局命令执行权。扩展进程崩溃后撤销其工具并显示错误，不让 Host 的会话或其他插件随之失效。JavaScript 扩展执行环境是受信任代码宿主，不宣称具备完整沙箱。

## 浏览器和 Canvas 的验收边界

浏览器工具可能需要额外浏览器引擎或执行进程，其体积和运行资源必须在 C1 中计入。已有浏览器可以作为用户显式配置的选项，但不能在默认发布测试中依赖开发机安装而隐藏成本。

Canvas 只能在运行时实际提供相应能力时启用。若其机制无法在 WKWebView 中安全适配，保留可复现限制，评估独立视图或迁移；截图和外链可以是明确的替代功能，但不等价于原 Canvas 兼容。首版必选项仍会阻塞 M5；可选项可明确延期。

## 交付物

兼容扩展清单、API 支持表、按需扩展宿主、三类受控样本、真实必选扩展测试、浏览器和 Canvas 能力报告。证据计划存入 `evidence/M5/`，列明每项资源和常驻进程开销。

## 验收门禁

- [ ] 至少一个文件或配置工具扩展、一个 MCP 提供扩展和一个声明式资源扩展通过 T09。
- [ ] M0 清单中的真实首版必选扩展全部通过；fixture 成功不代替真实扩展结果。
- [ ] 没有兼容扩展需求时不启动兼容宿主；纯资源可不启动；需求结束后的生命周期明确。
- [ ] 发布和激活记录没有未列入清单的编辑器扩展；传递依赖不会重新带回通用工作台。
- [ ] 缺失 API、激活失败、依赖循环、卸载和宿主崩溃可诊断；工具权限和拒绝路径有效。
- [ ] T10 的首版必选浏览器与 Canvas 能力实际可用；可选项有准确状态和限制，费用及资源计入对应配置。

## 风险与处理

若兼容一个扩展必须恢复完整 IDE，优先比较拆分工具、迁移 MCP 和放弃该扩展的产品成本；必选项的范围变更写入决策记录，不能自行通过降级标准关闭问题。维持 M4 原生插件模式可运行，避免兼容宿主成为核心任务的启动前提。
