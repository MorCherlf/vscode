# M8 网页与跨平台及热点原生化

状态：后续阶段，尚未立项。前置：M7 发布通过；各分支根据实际需求单独排期。对应目标：扩展 G01、G08、G09、G11、G12，不降低 macOS 首版已有标准。执行角色按选定分支分配。

## 目标与推进方式

网页、其他桌面平台和 Rust 热点替换是独立目标，不要求同批完成。只有选定的分支需要实现；未启动的分支不能标为已经支持。每个分支复用客户端核心、AHP 与验证资产，并在启动时补充精确范围、负责人、版本和证据位置。

## M8A 网页客户端

目标是让浏览器通过受支持的鉴权连接管理已有 Agent Host，而不是让浏览器直接获得本机文件和命令权限。

| 推进工作 | 交付与验收标准 |
| --- | --- |
| 将 Tauri transport 替换为网页连接适配，保留共享客户端核心 | 无 Tauri 运行时可加载网页界面，协议状态与桌面端一致 |
| 设计 HTTPS 页面、WSS 或同源代理、Host 鉴权和连接授权 | 恶意网页不能控制本地 Host；连接令牌不暴露在 URL 与访问日志中；不默认开放匿名公网监听 |
| 列出文件选择、凭据、通知、浏览器工具和 Canvas 等平台差异 | 不支持的桌面专属能力明确显示，不宣称网页与桌面天然一致 |
| 完成桌面与网页同会话、断线和任务流验证 | 适用的 T03 至 T08 通过，两个客户端状态收敛；浏览器和 Host 资源均计入性能报告 |

证据目录计划为 `evidence/M8A/`。若浏览器到本地服务受到平台限制，采用受支持的代理或远程 Host，不通过关闭安全边界让演示运行。

## M8B 其他桌面平台

默认顺序为 macOS x64、Windows、Linux；具体顺序按使用需求调整并记录。每个平台分别验证系统 WebView、Node 原生模块、命令执行、文件监视、凭据、签名和分发。

| 推进工作 | 交付与验收标准 |
| --- | --- |
| 为目标架构构建 sidecar、原生依赖和运行时 | 干净目标机器无 VS Code、系统 Node 和开发工具仍可启动 |
| 适配系统路径、shell、PTY、文件变化与凭据存储 | T01、T05 至 T09、T12 的适用场景通过，路径和命令语义不沿用 macOS 假设 |
| 验证安装、更新、回退、窗口和退出行为 | 目标系统的 T02、T13 通过；已有数据不因平台适配被破坏 |
| 建立目标系统自己的同能力基线 | 记录尺寸、启动和进程组资源，不把 macOS 结果作为其他平台成绩 |

每个平台单独保存 `evidence/M8B-平台架构/`。额外平台不得要求把 Electron 重新带回所有平台的发布包。

## M8C Rust 热点替换

目标是改善已经测出的瓶颈，而不是为了语言统一重写整个后端。候选包括 Diff、文件扫描、部分存储和传输计算；Copilot 运行时与既有扩展语义保持独立。

| 推进工作 | 交付与验收标准 |
| --- | --- |
| 从真实 profile 选择一个热点，固定输入和接口 | 有跨进程、序列化和内存开销在内的端到端基线；没有热点证据就不启动替换 |
| 实现可切换的 Rust 版本和原实现回退 | 确定性 fixture 中结果、取消、错误和边界行为一致，已有协议无需破坏性改变 |
| 使用同一数据集比较至少 30 次 | 默认采用门槛为该热点端到端 p95 改善至少 20%，且整组内存不回退；达不到则不替换默认路径 |
| 复验受影响功能与版本升级 | 对应 T 场景通过，迁移与回退可操作，维护成本和依赖变化有记录 |

证据目录计划为 `evidence/M8C/`。热点局部更快但跨语言总耗时更高时，不算成功。原生化目标可在立项前按实际瓶颈调整一次，不能在测试完成后追溯降低。
