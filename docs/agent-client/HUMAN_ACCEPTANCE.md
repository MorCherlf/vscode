# 四个人工验收点

日期：2026-10-29。用户指定的人工验收顺序为：1. 剪裁后的VSC Agent；2. 提供最小功能的DSH Bridge；3. 支持导入DSH插件的VSC Agent；4. 完整的Agent。下文沿用这四个名称，编号 H1–H4。

产品边界遵循 [ADR-001](ADR-001-agent-first-dsh-extension.md)：VSC Agent First，直接复用原组件与原扩展宿主，禁用编辑器专用插件，不主动加载 editor-only 组件；DSH 由 VS Code 插件适配，保留原运行时和插件行为；两个上游均保留更新路径。

## 交付与判定规则

四个验收点分别形成可运行交付，不等四项全部完成才给用户体验。当前优先 H1；DSH 已开始的代码保留，独立准备可以继续，但不把其完成作为 H1 提交验收的前提。

每项先完成相应工程验证，再交用户操作。状态区分“工程进行中、待本机构建/验证、可提交人工验收、人工通过、需修正”；只有用户明确确认才能记录“人工通过”。编译、自动化测试、静态审计、截图、模型回复或代理自行检查，都不能代替用户确认。未收到人工结果也不推断为通过；后续独立工作可以准备，不把等待人工体验变成所有工作的停工条件。

默认在用户本机 macOS arm64 验收。每次交付包含可获取的运行包、精确源码 SHA、依赖/运行时与插件版本、启动步骤、测试项目、演示步骤、已知限制和工程证据。云端若只有 Linux 构建或测试，准确标注“待 Mac 构建/验证”，提供本机执行步骤，不能称为已交付可验收的 Mac 包。运行包与步骤必须对应同一提交，后续提交不覆盖已交付验收版本的身份。

每项提供一个可复现的临时测试项目，用户无需在正在工作的项目上试验文件修改。原版组件和加载/激活等内部属性用工程证据辅助确认；人工主要操作实际产品与检查结果。测试专用 fixture 必须明确标识，H2/H3 的真实 DSH 与插件运行不能被 fixture 替代。

## H1：剪裁后的VSC Agent

**交付目标：** 先提供不依赖 DSH Bridge 的裁剪版原 VSC Agent。使用原 ChatWidget、ChatInputPart、会话列表及必要文本/diff/服务，保留同上游的真实交互，不用早期 React 原型代替。

**人工操作：**

1. 启动应用，选择测试项目；进入原 Agent 界面，新建并切换会话，输入、粘贴、多行与中文输入可用。
2. 使用已有、合法配置的原 Agent/provider，完成一次读取文件、修改文件、运行项目检查、查看只读 diff 的真实任务。
3. 体验流式回复、停止任务、权限批准/拒绝和继续会话，确认原 Agent 主流程没有因裁剪损坏。
4. 确认没有常规代码编辑、语言补全、调试等主入口；在运行证据中检查 editor-only 插件未被 startup、语言、命令或运行依赖激活，editor-only 启动模块/worker/服务未加载。
5. 在 DSH 未启用或未安装时重启并继续使用，确认 H1 不因等待 DSH 而失去可用性。

**通过标准：** 原组件真实运行，核心任务及审阅可操作；必要 Monaco/共享依赖有明确来源；编辑器专用插件和部件的排除有实际证据。只隐藏编辑区、只打开欢迎页或仅通过类型检查，不满足 H1。

**提交内容：** Mac 运行版本、测试项目/步骤、原组件来源、裁剪与负向加载清单、该版本真实任务和准入结果。当前新架构尚无 H1 人工通过记录，早期 Tauri 原型不回填为 H1 成果。

## H2：提供最小功能的DSH Bridge

**交付目标：** 提供可构建/加载的 DSH Adapter VSIX，在 H1 原界面中驱动真实 DSH 原运行时。此项先证明最小完整链路，不要求用户已能导入任意外部插件。

**人工操作：**

1. 在原 Agent 新建入口选择 DSH，配置实际需要的运行时、模型/凭据与测试项目。DSH 运行时/profile/版本可识别，未配置时错误明确。
2. 新建一个 DSH 会话，发送真实任务，看到流式内容、状态和完成结果；DSH 类型及历史出现在原会话列表，切换后回到同一会话。
3. 让原 DSH 执行至少一个内置工具，检查真实文件/检查结果与工具状态。DSH loop、工具执行链和 session log 保留原实现。
4. 关闭并重新进入该会话，验证最小历史恢复；触发一次配置/连接/进程错误，确认能诊断、恢复且不影响 VSC 原 Agent 路径。
5. 按当前能力体验停止/关闭：必须准确显示影响范围。若此阶段只能关闭专属于该会话的进程，应如实呈现；不能通过杀共享进程冒充逐会话取消。完整多会话隔离控制留在 H4，但受影响范围不明或错误标成功不合格。

**通过标准：** 原 UI → 真实 VSIX → 真实 DSH → 工具/会话结果 → 原 UI 的小链路可操作。必要的会话桥保持通用，DSH 专属逻辑在插件/驱动层。不能用独立新聊天页面、假的 runtime、固定字符串或只注册一个模型 provider 代替。

**提交内容：** H1 基础上的运行版本、Bridge VSIX、确切 DSH/profile/锁、配置/启动步骤、真实链路结果和最小能力限制。编译探针或 transport fixture 可作为辅助证据，不能代替本项人工演示。

## H3：支持导入DSH插件的VSC Agent

**交付目标：** 在 H2 基础上，提供真实用户可操作的导入、启用、禁用及恢复路径。此处“导入”指加入额外的原 DSH 包/插件组合，不是把内置插件重新列出来。

**人工操作：**

1. 从首轮明确支持的外部来源导入一个未预装的 DSH 插件，例如本地包、打包文件或固定版本 registry，至少有一种来源完整可用。查看原包名、版本、目标 profile 与启用状态。
2. 至少演示工具类与 hook/策略或上下文类两种能力：工具实际被调用；非工具插件在原链路中实际生效。原插件业务源码不为兼容而逐个改写。
3. 禁用插件，确认新任务不再获得其能力；重新启用并重启应用，确认状态和有效能力恢复，没有重复注册。
4. 导入不兼容或缺少依赖的测试包，确认错误可诊断、实际保存/激活状态准确，已有原 Agent 和 DSH 会话继续可用。
5. 对照同一 DSH 版本、profile、插件锁和策略的原生运行结果，核对工具副作用、hook/guard、上下文贡献、权限拒绝及生命周期。不同模型措辞不作为兼容失败，遗漏插件行为不能静默忽略。

**通过标准：** 用户完成“导入 → 能力生效 → 禁用 → 重启恢复”的完整生命周期，后端插件按原 DSH 机制运行。初版支持范围和不支持项可见；前端 DSH 插件若未支持，明确单独标级，不把后端导入成功扩展成所有前端插件可用。

**提交内容：** 带导入能力的 VSC Agent、插件样本与来源/版本、导入与生命周期步骤、原生行为对照、支持矩阵和错误/卸载说明。不得仅提供一段需要开发者手改配置才能凑出的运行截图作为可操作导入功能。

## H4：完整的Agent

**交付目标：** 在 H1–H3 基础上，闭合已冻结范围的日常 Agent 工作流和可维护性。完整仍指 Agent First 范围，不包括恢复传统 IDE 或任意 VSC/DSH 插件无条件兼容。

**人工操作与检查：**

1. 在两个测试项目、多个会话间使用原 VSC Agent 路径及 DSH 路径，完成读取/修改/命令/审阅/恢复任务；会话、草稿、工具结果和权限不串用。
2. 验证流式输出、提问、计划、审批拒绝、模型/工具错误、取消、断线重连和应用重启；取消一个会话不结束另一个，迟到批准无效，未知副作用不自动重放。
3. 使用冻结清单内的 VSC Agent 扩展、DSH 工具/hook/context/compaction 等必选插件；需要原 DSH 前端的必选能力使用其原 client graph/renderer，未纳入首版的能力明确展示状态。
4. 检查导入、升级、禁用、卸载、诊断与版本信息；既有会话恢复交回原拥有者，错误不虚构成功或用新会话替代旧历史。
5. 检查 VSC 和 DSH 各一次真实上游升级、行为回归及版本/数据回退记录；两边不因更新形成无法解释的核心补丁或插件源码改写。
6. 体验约定规模的历史、长任务和中文输入/切换，结合相同能力的全进程/依赖测量确认性能预算；没有依靠关闭必选插件或漏算 DSH 达标。

**通过标准：** 全部冻结的功能与插件必测项通过，无未处理的数据丢失/权限绕过/会话串用；用户可按正常流程完成任务。AF-01–06、G01–G12 分别提供对应证据，不能用一次顺利演示替代故障/升级验证。

**提交内容：** 完整 Mac 候选版本、功能/插件/版本支持表、真实任务与故障/升级/性能结果、恢复说明和残余限制。签名、公证、干净机器、更新等正式发行门禁按 GOALS/VALIDATION 保留；H4 的人工功能确认不等于应用已发布或这些门禁自动通过。

## 每次提交人工验收的交接格式

每项在 `evidence/AF/H1/` 至 `evidence/AF/H4/` 或同等清晰位置记录：

- 验收点、精确提交/包标识、平台、构建与依赖版本。
- 运行包位置和启动步骤，所需测试项目及自行配置项目。
- 按本页步骤的演示结果、工程检查、真实/fixture 边界和未完成项。
- 当前状态、用户反馈原文或链接、反馈对应版本，以及修复后需重验的步骤。

当前四个人工点均未有用户通过记录。工程进度由云端在相应交付证据中更新，人工结论只在用户确认后写入；已有不受影响的结果可以复用，未通过项继续修复。
